1. Segurança (críticos)

T1.1Bind do backend está em 127.0.0.1 (não exposto na LAN)CRÍTICO
Com o app rodando, em outro terminal:
netstat -ano | findstr :8000
✅ Esperado: apenas 127.0.0.1:8000 ... LISTENING. Nenhuma linha com 0.0.0.0:8000.
❌ Se aparecer 0.0.0.0:8000: ainda há um processo antigo rodando — mate todos os python.exe e suba de novo.
T1.2API não responde de outra máquina na LANCRÍTICO
De outra máquina na mesma rede (ou de um celular no Wi-Fi corporativo), tentar:
curl http://<IP-da-sua-máquina>:8000/hosts
✅ Esperado: conexão recusada / timeout. Não pode retornar a lista de hosts.
❌ Se retornar dados: ⚠️ revise NT_API_HOST e a configuração de firewall.
T1.3Terminal externo (PowerShell) não vaza senha no históricoCRÍTICO
No app, abrir um host com WinRM funcionando, clicar em "Abrir Terminal Externo" com credenciais.
Na janela do PowerShell que abriu, digitar:
Get-History | Format-List
Get-ChildItem env: | Where-Object { $_.Name -like "NT_*" }
✅ Esperado: nenhum comando contendo a senha em texto claro. As variáveis NT_REMOTE_* não devem aparecer (foram removidas no início do script).
❌ Se aparecer a senha em $pass ou em Get-History: a refatoração do open_external_terminal não rodou — confirme que copiou python/api/routes/network.py.
T1.4IPC do Electron rejeita argumentos maliciososCRÍTICO
No app, abrir DevTools (Ctrl+Shift+I) → Console. Executar:
await window.electron.ipcRenderer.invoke('launch-rdp', '1.1.1.1 & calc.exe')
✅ Esperado: erro "Invalid host". Calculadora não deve abrir.
Repetir para os outros handlers:
await window.electron.openExternal('javascript:alert(1)')   // deve dar Invalid URL
await window.electron.showItemInFolder('..\\..\\Windows')   // deve dar Invalid path
✅ Esperado: todos rejeitam.

3. Multi-domínio / Multi-VLAN ⭐

Pré-requisito desta seção: máquina conectada a pelo menos duas redes diferentes (duas NICs físicas, ou uma NIC + VPN, ou uma NIC + Hyper-V/WSL). Se você só tem uma, pule para o item 4.
T3.1Endpoint /network/interfaces detecta TODAS as NICs ativasnovo
curl http://127.0.0.1:8000/network/interfaces
✅ Esperado: JSON com uma entrada por NIC IPv4 que não seja loopback (127.x) nem APIPA (169.254.x). Cada uma com name, ip, cidr, mac.
❌ Se vier vazio: confira que psutil está instalado.
T3.2Aba "Redes / VLANs" em Configuraçõesnovo
Abrir o app → Configurações. Confirmar que existem 4 abas: Scanner de Rede / Redes / VLANs / Acesso Remoto / Dados.
Clicar em "Redes / VLANs". Conferir os blocos:
  • Interfaces detectadas — mostra suas NICs locais. Botão "Importar" em cada.
  • Redes gerenciadas — vazio na primeira vez, com botão "Adicionar rede".
Clicar em "Importar" em cada NIC. Cada importação adiciona uma rede com nome = nome da NIC e source_ip preenchido.
Para cada rede importada, preencher (se aplicável):
  • Nome: ex. "Domínio A — VLAN admin"
  • DNS server: ex. 10.10.0.1
  • Domínio AD: ex. dominio-a.local
Clicar em Salvar Alterações.
✅ Esperado: toast verde de sucesso. Recarregar a página → as redes persistem.
T3.3⭐ Ping com source_ip sai pela NIC corretaCRÍTICO
Abrir Wireshark. Filtrar por icmp. Selecionar a interface da NIC #1.
No app: Ferramentas → Ping. No dropdown "Sair pela rede", escolher a rede da NIC #1. Pingar 8.8.8.8.
✅ Esperado: Wireshark vê pacotes saindo. Source = IP da NIC #1.
Parar. Trocar para a NIC #2 no dropdown. Pingar de novo. Mudar Wireshark para a outra NIC.
✅ Esperado: agora os pacotes saem pela NIC #2. Confirma que o -S/-I está funcionando.
❌ Se sair sempre pela mesma NIC: o flag não está chegando ao comando ping. Confira python/src/network/ping.py linha ~30.

✅ Esperado: a primeira linha do tracert mostra o gateway da NIC selecionada (não o gateway default).

4. Estabilidade (DB, polling, race conditions)

T4.1SQLite sob carga (simular o cenário real)alto
Cadastrar 50+ hosts (importe um CSV se já tiver, ou faça discovery em uma /24).
Habilitar monitoramento de todos.
Em paralelo, abrir o Scanner de Rede e iniciar uma nova varredura. Mexer no Painel (mudar grupos, filtros).
✅ Esperado: sem mensagens de database is locked nos logs. Status atualiza normalmente.
❌ Se aparecer locks: verificar logs do backend — o decorator @_retry_on_locked deveria absorver a maioria.
T4.2Polling com backoff quando backend cainovo
Com o app aberto, matar o processo do backend Python:
Get-NetTCPConnection -LocalPort 8000 -State Listen | ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
No DevTools → Network, observar as chamadas /hosts e /network/monitor.
✅ Esperado: intervalos entre chamadas aumentam exponencialmente (2s → 4s → 8s → ... até 30s). Toast: "Servidor não responde. Tentando reconectar..."
Subir o backend de novo.
✅ Esperado: dentro de no máximo 30s aparece toast verde "Conexão com o servidor restaurada." e os pings voltam a ser de 2s em 2s.
T4.3Polling do cofre menos agressivobaixo
DevTools → Network. Filtrar por security/status. Aguardar 1 minuto.
✅ Esperado: aproximadamente 2 chamadas/min (era ~12/min antes).
T4.4Memória estável após 30 minutosbaixo
Deixar o app rodando 30 minutos com monitoramento ativo. Anotar uso de memória do processo Electron no início e no fim (Task Manager).
✅ Esperado: crescimento < 50MB. Sem leak agressivo.

7. Troubleshooting

Backend não sobe / API offline
  1. Verificar log: %TEMP%\network_tools_debug.log
  2. Verificar porta presa: netstat -ano | findstr :8000
  3. Subir backend isolado pra ver o erro real: cd python && python -m api.server
"ModuleNotFoundError: No module named 'dns'"

Falta rodar pip install -r python/requirements.txt (T0.1). O dns_resolver.py tem fallback para socket, mas só se o import falhar com ImportError. Outros erros (ex: WMI no Windows) também caem no fallback.

Aba "Redes / VLANs" não aparece em Configurações

Você está rodando uma build antiga. Certifique-se de que electron/dist/ foi regerado (npx vite build) e que está abrindo o app a partir do diretório principal (C:\Users\raphael.rego\Desktop\ferramentasderede\), não de qualquer outro lugar.

Ping/traceroute "saem" sempre pela mesma NIC
  1. Confirmar que a rede tem source_ip preenchido em Configurações → Redes.
  2. Conferir no Wireshark antes de mexer (controle): qual é a NIC default.
  3. Rodar manualmente: ping -S <source_ip> 8.8.8.8 direto no cmd. Se isso também falhar, é problema de roteamento no Windows, não da app.
Erro CORS no DevTools

O CORS agora só permite http://127.0.0.1:5173 e http://localhost:5173. Se você abriu a UI por outra origem (ex: http://192.168.1.10:5173), defina antes de subir o backend:

set NT_CORS_ORIGINS=http://192.168.1.10:5173
python python\main.py
Erros TypeScript depois de mexer no código

Rode cd electron && npx tsc --noEmit e leia a primeira linha do erro. Os tipos críticos vivem em electron/src/types.d.ts e electron/src/pages/Settings.tsx (NetworkConfig).
